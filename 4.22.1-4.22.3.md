# FalkorDB 4.22.1 vs 4.22.3 — medium benchmark comparison

Date: 2026-11-05  
Tool: `scripts/run_medium_benchmark.sh`  
Dataset: medium Pokec (100,000 nodes / 1,768,515 edges)  
Workload: 10,000 queries, `parallel=8`, target `mps=2000`, `write_ratio=0`  
Client query timeout: `FALKOR_QUERY_TIMEOUT_MS=20000`

| Role | Version | Endpoint | Container / label |
|------|---------|----------|-------------------|
| Primary | **4.22.1** (module ver 42201) | `falkor://127.0.0.1:6380` | `bench-falkor-4.22.1` → results `falkordb-c` |
| Secondary | **4.22.3** (module ver 42203) | `falkor://127.0.0.1:6800` | `bench-falkor-4.22.3` → results `falkordb-rs` |

Other engines disabled (`RUN_NEO4J/MEMGRAPH/POSTGRES/MONGO/TIGERGRAPH/SPANNER=0`).

> Note: the script labels the secondary Falkor instance as `falkordb-rs` even when both sides are release Docker images. Mapping for these runs is primary port **6380 = 4.22.1**, secondary port **6800 = 4.22.3**.

### Overall

### Deep-hop failures (both versions)

Extended-core adds deep traversals that hit the **20s client timeout** on both builds (reported as failures, not global timeouts):

| Query | fail% 4.22.1 | fail% 4.22.3 | p99 4.22.1 | p99 4.22.3 |
|-------|-------------:|-------------:|-----------:|-----------:|
| `exact_6_hop_traverse_count` | **75.4%** | **75.9%** | 19137 ms | 19005 ms |
| `exact_5_hop_traverse_count` | **10.3%** | **10.8%** | 15335 ms | 15204 ms |

Other heavy tails present on both sides with similar shape:

| Query | p50 4.22.1 | p50 4.22.3 | p99 4.22.1 | p99 4.22.3 |
|-------|-----------:|-----------:|-----------:|-----------:|
| `all_shortest_paths_len` | 25.0 ms | 29.2 ms | 1851 ms | 1892 ms |
| `shortest_path` | 50.4 ms | 53.8 ms | 116 ms | 120 ms |
| `shortest_path_with_filter` | 52.7 ms | 54.5 ms | 109 ms | 119 ms |

### Extended-core verdict

**No clear degradation of 4.22.3 vs 4.22.1 on extended-core.**

- Global metrics stay within ~0–5% (run-noise territory).
- 4.22.3 is slightly worse on p50/p95, slightly better on avg/p99.
- Throughput and wall time are essentially tied.
- Failure rates are effectively the same; deep 5/6-hop queries are hard for **both** under this timeout/load.

Compared with baseline (0 errors, ~10 ms avg, ~780 qps): extended-core is much heavier overall because of deep hops, but the **version-to-version** gap remains small.

## 3. Combined conclusion

| Profile | Noticeable 4.22.1 → 4.22.3 regression? |
|---------|----------------------------------------|
| **baseline** | **No** (~1% noise, 0 errors) |
| **extended-core** | **No** (~0–5% noise; same deep-hop failure pattern on both) |

**Bottom line:** On medium dual-instance Docker runs, FalkorDB **4.22.3 does not show a noticeable performance degradation versus 4.22.1** for either baseline or extended-core. The expensive extended-core 5/6-hop queries fail at high rates on both versions under the default 20s client timeout and are not a version-specific regression.
