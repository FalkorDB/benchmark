## Write queries

Write-family ops accounted for **~449 / 10,000** samples on 4.22.1 (~4.5%), consistent with `WRITE_RATIO=0.05`. Per-query counts are small (**n ≈ 40–62**), so percentile swings should be treated as noisy.

### Write-path notes

- Most write queries are **similar** on p99 between versions (within a few percent).
- **`detach_delete_user`** looks worse on 4.22.3 at p50 (108 → 350 ms) and p99 (+28%).
- **`single_vertex_update`** p99 is higher on 4.22.3 (+35%).
- With only ~50 samples each, these tails are **not strong evidence** of a systematic write regression by themselves.

## Verdict

**No clear overall regression of FalkorDB 4.22.3 vs 4.22.1** on medium baseline with 5% writes.

| Signal | Observation |
|--------|-------------|
| Correctness / stability | Both: 10k/10k success, 0 errors, 0 timeouts |
| Avg / p99 / throughput / wall time | Flat or slightly **better** on 4.22.3 |
| p50 | **~19% higher** on 4.22.3 (median latency worth noting) |
| p95 | **~10% better** on 4.22.3 |
| Individual write tails | Mixed; a few queries worse on 4.22.3 but small **n** |

**Bottom line:** Under baseline + 5% writes, 4.22.3 does not show a broad performance degradation versus 4.22.1. Global avg/throughput/p99 are essentially tied (or slightly favor 4.22.3). The main caution is a higher **p50** on 4.22.3 and a couple of write-query tails (`detach_delete_user`, `single_vertex_update`) that look worse in this sample and may deserve a focused re-run with more write samples.
